# Constants

BoltFFI exports two kinds of constants:

- A global constant is a standalone Rust `const` marked with `#[export]`.
- An associated constant belongs to an exported record, enum, or class.

Both forms produce immutable values in the generated API. BoltFFI emits simple literals directly in generated source and reads values that require Rust evaluation through a generated native accessor.

Use a global constant for a value that belongs to the package as a whole. Use an associated constant when the value describes a particular record, enum, or class.

## Global constants

Mark a standalone public constant with `#[export]`. Swift, Kotlin, TypeScript, and Python expose it at module scope. Java and C# place it on the generated module class because those languages do not have module-level values.

The Rust name is converted to the naming convention of each target. `API_VERSION` becomes `apiVersion` in Swift, Kotlin, and TypeScript, `API_VERSION` in Java, `ApiVersion` in C#, and `api_version` in Python.

## Associated constants

Associated constants are declared inside the same exported impl blocks used for methods and constructors:

- Use `#[data(impl)]` for a struct or enum marked with `#[data]`.
- Use `#[export]` for a class impl.

Every public constant in the marked impl is generated on its owner type. The constant may use `Self` or any other supported constant type. The impl marker exports the member, so the individual constant does not need another `#[export]` attribute.

## Data constants

Every record or enum marked with `#[data]` can be the value type of a global or associated constant. This includes primitive-only records, encoded records, C-style enums, and data enums. The selected target must already support that data type as a normal return value.

The `Color` and `Mode` declarations above are examples of associated data constants. The same data types also work as global constants:

Values such as `Color { ... }` are constructed in Rust and delivered through a generated accessor. The generated API still exposes an ordinary immutable value.

## Supported values

A constant's declared type follows the same support rules as a function return type. Rust must also permit the value in a `const` declaration.

| Rust constant | Examples | Generated delivery |
|---------------|----------|--------------------|
| Boolean | `bool` | Inline |
| Integer | `u8`, `i32`, `u64`, `usize` | Inline when the value fits the declared type |
| Floating point | `f32`, `f64` | Inline |
| String | `&str`, `&'static str` | Inline for string literals |
| C-style enum | `Mode::Fast`, `Self::Fast` | Inline |
| Byte data | `&'static [u8]` | Native accessor |
| Tuple | `(u32, u32)` | Native accessor |
| `#[data]` record | `Color`, `Point` | Native accessor |
| `#[data]` enum | `Mode`, `State` | Inline for a C-style variant or native accessor for an encoded value |
| Computed expression | `6 * 7`, `Self { ... }` | Native accessor when it cannot be represented inline |

Inline and accessor-backed constants have the same public API. The distinction only controls how BoltFFI delivers the value.

## Limits

Most constant restrictions come from Rust's const evaluator and the normal return-type support of each target.

### Global constants

- Each global constant needs its own `#[export]` marker.
- A global constant cannot use `Self` because it has no owner.
- Java and C# expose global constants on the generated module class.

### Associated constants

- The owner must be an exported record, enum, or class.
- Record and enum constants belong in `#[data(impl)]`; class constants belong in `#[export]`.
- Only public constants become part of the generated API. Private constants remain available to the Rust implementation, and `#[skip]` can omit a public constant.
- A C-style enum associated constant must alias a variant of that same enum when C# is generated. C# enums cannot contain static fields or properties. A primitive or record constant intended for all targets can instead be placed on a record or class, or exported globally.

### Constant values

- The expression must be valid in a Rust `const` declaration.
- The declared type must be supported as a return value by every selected target.
- Borrowed constants are limited to `&str` and `&[u8]`. Records and enums are exported by value rather than by reference.
